# Codebase review, 2026-11-10

A read-only review of the whole repository, asked for as "architectural and important improvements, bloat and inefficiencies to clean up, removing as helpful as adding".
This file is the handoff: every finding, where it lives, and the change proposed, so an agent can pick items up without the original conversation.

## How to use this file

- Line numbers are as of commit `f68ce4c` on branch `tool-fixes`; they drift, so find the code by the symbol named beside each one.
- Mark an item by editing its **Status** line to `done: <commit>` or `skipped: <why>`.
- Each item says how it was confirmed.
  **Checked** means the lead reviewer read the cited lines and they say what the item claims.
  **Reviewer's read** means one area reviewer read the code and its callers, and the lead did not re-check.
  **Suspected** means nobody confirmed it; confirm before acting.
- No speed-up here was measured; they are inferred from reading. Measure before and after on anything in section C.
- Read `AGENTS.md` and `docs/principles.md` first. Bugs want a failing test before the fix. No build step, bundler, TypeScript, framework or DI container is on the table.
- Paths are relative to the repository root; `src/Pintura/` is abbreviated to `P/` and `src/Pintura.Tests/` to `T/`.

## Overall verdict

The codebase is in good shape.
The compiler plus unused-code analyzers find no unused private member and no unreferenced type, no CSS selector is orphaned, no top-level JS function is unreferenced, every payload field is read, and every API route has a caller.
The wins are a handful of real bugs, knowledge written twice, and redundant work on hot paths.

## Suggested order

1. A1, A2, A3: a destructive install script, a write-back bug that can erase an agent's save, and the fixtures' "must check clean" rule not being enforced.
2. C1, C2, C4: the server's unconditional reloads, git spawns, and scenes rebuilt eight times per check, since those shorten the loop agents work in.
3. A4 with B1 to B5: each removes a place where two copies can drift.
4. D and E whenever convenient; they are small and independent.

## A. Fix first: bugs and hazards

### A1. `install.sh` can delete a directory that isn't Pintura's

- **Status:** done: 191e7f5
- **Where:** `install.sh:22-23` (guard), `install.sh:45` (`rm -rf "${application_directory}"`).
- **What:** the guard uses `-e` and accepts any directory holding an entry named `pintura` or `Pintura`, including a folder.
  With `PINTURA_INSTALL_DIR=~/src` and a clone at `~/src/pintura`, the guard passes and the script removes `~/src`.
- **Change:** test for a file only a release has, such as `[ -f "$dir/Pintura.dll" ]`.
  `install.ps1:13` already checks for the `Pintura.exe` file.
- **Confirmed:** checked.

### A2. An edit's rollback can erase an agent's concurrent save; four rollback implementations, three locks

- **Status:** done: 5a4a9d8
- **Where:** `P/Server.cs:402-431` (`PreviewServer.Patch`, the `before` read at `:411`), `P/Server.cs:465-527` (`Move`), `P/Server.cs:538-554` (`Put`), `P/Comments.cs:412-447` (`CommentFile.Rewrite`), `P/Picks.cs:553-635` (`PickFile.Touched`), `P/Patcher.cs:82-105` (`Patcher.Rewrite`).
- **What:** `Patch` reads `before` outside the patcher's lock and separately from `Rewrite`'s own read.
  If an agent saves the file between the two reads, a later rollback `Put(before)` erases that save, and `PageEdits.Wrote` records the wrong text.
  Only `Patcher.Rewrite` and `CommentFile.Rewrite` check that the file hasn't changed since it was read; `Put` and `Touched.Restore` check nothing.
  The locks `Patcher.FileGate`, `CommentFile.Gate` and `PickFile.Gate` are separate, and `presentation.yaml` is written under `FileGate` (move) and under `PickFile.Gate` (`P/Picks.cs:272`, `:323`), so `/api/move` and `/api/picks` can interleave on it.
- **Change:** move `Touched` (Track, Write, Restore, with its `Before` map) into `P/Files.cs` as one file transaction with the changed-since check built in, have `Patcher.Rewrite` return the text it actually read, and use the transaction in all four places.
  Then one `PreviewServer.Write(store, ...)` wrapper holding a single server write lock replaces the shape `Edit`, `Move`, `Comment`, `Pick` and `Revert` all repeat (`P/Server.cs:334-614`): the "doesn't load" guard, the try/catch, `PageEdits.Wrote`, `Refresh`, the `{Version, Undo}` answer.
- **Win:** the bug, one conflict rule, about 140 lines.
- **Confirmed:** the separate read at `:411` is checked; the race, the lock overlap and the line counts are the reviewer's read.

### A5. A failure partway through an export throws away billed work

- **Status:** done: 45fa0e5
- **Where:** `P/Editide.cs:123-159` (only 429 is retried), `P/Exporter.cs:295-298` (`Write`'s `finally` deletes the scratch folder), `P/Exporter.cs:386` (`Place` moves the manifest after the deck).

## G. Checked and found fine

Don't re-examine these without a new reason.

- **Local server safety:** the preview binds `localhost` and headless servers `127.0.0.1`; the Host header is checked against DNS rebinding; `Sec-Fetch-Site` blocks cross-site and same-site requests to `/api`; non-GET requests need a loopback Origin or none; JSON body binding refuses form posts.
- **Edit confinement:** a slide file is used only if the presentation has that slide; theme and layout files are matched by name against the theme's own; `presentation.yaml` takes only field and section paths; media is served only from the loaded set.
- **Script injection:** the only `innerHTML` is the constant icon set; presentation content goes through `textContent` or the CSSOM; links are limited to http, https and mailto (`P/Markup.cs:403-405`); served SVGs get a sandbox CSP and `nosniff`; `SvgPaint` ignores DTDs.
- **Credentials:** the API key is kept at 0600 on Unix and under DPAPI on Windows, written only after `whoami` accepts it, and the API address must be https or loopback http.
- **Dead code:** no unused private member, unreferenced type, orphan CSS selector (apparent orphans are prefix-built, such as `kind-${kind}`), unreferenced top-level JS function, unread payload field, or uncalled API route.
- **One slide renderer:** app, grid, picks, theme, compare, headless and export all draw through `mountStage` and `renderStage`.
- **Design claims that hold:** a multi-edit request is validated whole before any write; a patch whose source no longer matches is refused; revisions are read straight from git; axis min, max and step come from C# and the page only ticks them; an unchanged deck re-exports with no calls.
- **Atomic writes:** `Files.Replace`, the picture cache, `DeckReads` and the SVG raster cache all write to a temp file and move.
- **Docs coverage:** all 115 literal YAML keys in the loader, comments, picks and books appear in `docs/topics`, and the reverse; every CLI flag is documented somewhere; the topic list is tested against the files.
- **Healthy tests:** `PatcherTests` (113 pure tests in 0.6s), `ExporterTests` (assert the tool-input contract), the node tests (177 in 0.44s, run in CI).
- **Not findings:** almost nothing is shared with Libreta as copied code, so a shared library isn't worth extracting; ES modules would break the HTML export's inlining and the `require`-based node tests; the hard-coded PowerPoint defaults in `Scene.cs` (gap width 150, series colors accent1 to accent6) look deliberate, given the `Resolved` doc comment.
